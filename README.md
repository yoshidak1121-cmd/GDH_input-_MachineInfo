# GDH 入力・機械情報管理リポジトリ

このリポジトリは、GDH 向けのフロントエンド試作・仕様整理をまとめたものです。現在は主に次の 2 つの Web 画面を含みます。

- **NCサービス情報登録システム**（`index.html`）
- **設置台数・稼働台数管理システム**（`machine_info.html`）

いずれも **HTML / CSS / JavaScript による静的フロントエンド実装**で、バックエンド API は同梱していません。現状の保存先はブラウザの `localStorage` で、将来的な API / DB 連携を想定した画面・データ構造の整理が行われています。

---

## 収録している画面

### 1. NCサービス情報登録システム

`index.html` から起動する、NC サービス情報を登録・管理する画面です。

#### 対応している主な機能

| 画面ID | 画面名 | 概要 |
|---|---|---|
| S01 | 一覧・検索画面 | 登録済み NC 情報の検索・絞り込み・新規登録開始 |
| S02 | 新規登録開始画面 | NC シリアル番号入力と重複チェック |
| S03 | 基本情報登録 | NC 情報・機械情報・NC 販売情報の入力 |
| S04 | 輸出・設置情報登録 | 輸出先・現地販売店・エンドユーザ・設置日の入力 |
| S05 | 契約情報登録 | 契約情報の複数行登録、追加・削除・コピー |
| S06 | 確認画面 | 登録前確認と最終バリデーション |
| S07 | 登録完了画面 | 完了表示と次操作の選択 |
| S08 | マスタ簡易登録ダイアログ | NC システム型名・MTB などの簡易追加 |
| S09 | 下書き・未完了一覧 | 入力途中データの再開・削除 |
| M01-M07 | マスタ管理画面 | 各種マスタの表示・有効化 / 無効化 |

#### 画面遷移

```text
S01 一覧・検索
  ↓ 新規登録
S02 新規登録開始（NCシリアル番号入力）
  ↓ 次へ
S03 基本情報登録
  ↓ 下書き保存 → S07（下書き完了）
  ↓ 次へ
S04 輸出・設置情報登録
  ↓ 次へ or スキップ
S05 契約情報登録
  ↓ 確認へ or 契約なしで確認へ
S06 確認
  ↓ 登録
S07 登録完了
```

#### 登録ステータス

| ステータス | 条件 |
|---|---|
| 下書き | NC シリアル番号のみ、または主要情報不足 |
| 基本情報登録済み | Step 1 まで完了 |
| 設置情報登録済み | Step 2 まで完了 |
| 契約情報登録済み | 契約情報が 1 件以上ある |
| 契約未登録 | 基本情報はあるが契約 0 件 |
| 要確認 | 警告項目あり |
| 登録完了 | 必須・主要項目が充足 |

#### マスタデータ

| ID | マスタ名 | ファイル |
|---|---|---|
| M01 | NCシステム型名マスタ | `data/nc_system_master.json` |
| M02 | MTBマスタ | `data/mtb_master.json` |
| M03 | 販売会社マスタ | `data/sales_company_master.json` |
| M04 | サービス拠点マスタ | `data/service_base_master.json` |
| M05 | 国コード ISO2 マスタ | `data/country_master.json` |
| M06 | 契約者区分マスタ | `data/contract_holder_type_master.json` |
| M07 | 契約タイプマスタ | `data/contract_type_master.json` |

#### マスタ共通ルール

- `is_active: false` の値は新規入力時の候補に表示しない
- 既存データで使用中の値は「表示名（無効）」として扱う想定
- コード値は登録後の変更を原則不可とする前提
- 物理削除ではなく `is_active` による無効化前提

#### バリデーション要点

**エラー（保存不可）**
- NC シリアル番号は必須かつ重複不可
- 契約行がある場合、契約タイプ・契約期間（月数）・契約開始日は必須
- メモ欄は 300 文字以内

**警告（保存可能）**
- 機械輸出日 < NC 販売日
- 設置日 < 機械輸出日
- 契約開始日 < 設置日
- 同一 NC 内で契約番号が重複

#### 契約情報仕様

- NC 基本情報に対して複数の契約情報を登録可能
- 契約終了日は `契約開始日 + 契約期間（月数） - 1日` で自動計算
- 契約追加時は、ご契約者 / 契約受託会社 / 契約タイプ / 契約期間 / 契約開始日などの初期値が設定される想定
- 契約コピー時は契約番号・開始日・メモをクリア

### 2. 設置台数・稼働台数管理システム

`machine_info.html` から起動する、海外拠点向けの暫定入力システムです。

#### 目的

- 設置台数データと稼働台数データを Web 画面から入力・確認する
- 拠点担当者と HQ 担当者のワークフローを模擬する
- 将来の DataHub 連携を見据えた項目・画面・運用イメージを整理する

#### 主な画面

| 画面 | 概要 |
|---|---|
| ログイン | デモユーザー選択（HQ / 各拠点） |
| 設置データ一覧・登録 | 設置台数データの検索・登録・CSV出力 |
| 稼働台数メンテ一覧・登録 | 稼働台数データの検索・登録・下書き保存 |
| サービス情報一覧・登録 | 設置データに紐づく契約 / サービス情報の管理 |
| チェック・確認 | 拠点担当者による提出前確認 |
| 承認・差戻し | HQ 担当者による承認・差戻し |
| 集計レポート | 拠点別・年度別・MTB別・精度別の集計表示 |

#### ロール

| ロール | 権限 |
|---|---|
| `site_staff` | 自拠点データの閲覧・入力・提出 |
| `hq_staff` | 全拠点データの閲覧・承認・差戻し |

#### データ管理イメージ

- `installation_base` : 設置台数データ
- `active_maintenance` : 稼働台数メンテデータ
- `issue_list` : 差戻しコメント管理
- サービス情報 : 設置データに紐づく契約情報

#### ステータスフロー

```text
Draft → Submitted → Under Review → Approved / Locked
                                ↘ Returned → 修正 → Submitted
```

## 起動方法

このリポジトリは `data/*.json` を `fetch` するため、`file://` ではなくローカルサーバ経由で起動してください。

### 例: Python の簡易サーバを使う

```bash
python -m http.server 8080
```

起動後、次の URL にアクセスします。

- NCサービス情報登録システム: `http://localhost:8080/index.html`
- 設置台数・稼働台数管理システム: `http://localhost:8080/machine_info.html`

### 補足

- フロントエンドのみで動作します
- データ保存先はブラウザの `localStorage` です
- ブラウザごと・端末ごとに保存内容は分離されます
- 実運用向けの永続化や認証は未実装です
